## 3. 引言

### 3.1 目的

本文档定义 EquipmentMonitor 上位机软件的**功能需求、性能需求、接口需求、权限需求、环境需求和验收标准**，
作为开发、测试、验收和变更的基线。

### 3.2 范围

本软件运行于 Windows 10 工控机，作为 **Modbus TCP Client/Master**（并兼容 Modbus RTU/串口、MQTT 等既有通道），
与 PLC 进行数据读写，负责显示、控制指令下发、报警、历史存储、权限与审计。
**实际执行、安全联锁、急停、限位、硬件保护由 PLC 或硬件完成**。
本次软件变更（[ChangePlan.md](ChangePlan.md)）的范围：**元件（先伺服）的操作接口与操作界面（HMI 替代）**。

### 3.3 读者对象

甲方、PLC 工程师、软件开发、测试、运维、验收人员。

### 3.4 术语

| 术语 | 说明 |
|---|---|
| 上位机 | 本软件，运行于工控机 |
| 下位机/PLC | 执行设备，Modbus TCP Server/Slave |
| Modbus TCP | 通信协议 |
| Client/Master | 上位机角色 |
| Server/Slave | PLC 角色 |
| Unit ID | 从站标识 |
| 点表 | 变量地址与属性清单 |
| 寄存器/线圈 | Modbus 数据区 |
| 字节序 | ABCD/CDAB/BADC/DCBA（当前仅实现 ABCD 高字在前，见 §15.1） |

| 元件 | 机台内部的伺服、气缸、传感器或监控设备（本系统的操作对象） |
| 机台 | 一台被监控设备的逻辑单元（可含多个元件） |
| PLCopen | 运动控制功能块国际标准（MC_Power/MC_Home/MC_MoveAbsolute…），本软件操作接口的蓝本 |

## 4. 总体描述

### 4.1 项目背景

[简述项目来源、现场设备、工艺目标]

### 4.2 系统目标

- 实时采集 PLC 数据并显示。
- 按权限向 PLC 写入控制指令和参数（伺服操作按 PLCopen 单轴语义）。
- 报警提示、确认、记录。
- 历史数据、操作审计、报表导出。
- 无网络（无外网）环境下稳定运行。

### 4.3 用户角色

| 角色 | 对应系统等级 | 说明 |
|---|---|---|
| 操作员 | Operator | 查看、确认报警、有限操作（设备启停/伺服使能与定位） |
| 工程师 | Engineer | 参数修改、手动调试、诊断 |
| 管理员 | Administrator | 用户管理、点表配置、日志审计、备份 |
| （只读访客） | Viewer | 仅查看监控画面（可选启用） |

### 4.4 运行环境

- 操作系统：Windows 10 [LTSC 2019/2021/专业版]
- 硬件：工控机 [CPU/内存/硬盘]
- 显示器：[1366×768 / 1920×1080]
- 输入：**鼠标、键盘，无触摸屏**
- 网络：与 PLC 同一局域网，**无外网**
- 数据库：SQLite（`data/equipment.db`，WAL，BusyTimeout 5000ms）
- 框架：.NET 8 + WinForms（控件库 AntdUI）
- 其他：Serilog 日志（分模块文件 + 内存缓冲）

### 4.5 约束与假设

- PLC 支持 Modbus TCP Server。
- 现场网络稳定，端口 [502] 开放。
- 无外网，不依赖云服务、CDN、在线授权；安装包自包含。
- 安全联锁、急停、硬件保护由 PLC/硬件完成；**本软件不承担安全功能**。
- 工控机时间需准确，可手动校准或由 PLC 提供。
- 会话空闲超时 30 分钟（可在配置中调整）。

## 9. 权限需求

**访问决策模型（实测）**：`(安全等级 Low/Medium/High × 角色 Viewer/Operator/Engineer/Admin) → 权限集合 + 二次确认集合 + 审计要求`，
共 12 种组合**必须全覆盖**（缺任一条启动失败），配置在 `appsettings.json` 的 **`Security:AccessRules`**。
登录后由 `SecurityLevelPolicy` 决定当前会话等级；`ConfirmMode: CurrentUser` 表示二次确认验证当前用户密码。

当前默认授权（括号内为达到该权限所需的最低等级）：

| 功能（权限点） | 操作员 | 工程师 | 管理员 | 只读访客 |
|---|---|---|---|---|
| 查看实时数据 / 确认报警（MachineView） | 是 | 是 | 是 | 是 |
| 查看系统日志与审计（LogView） | 是 | 是 | 是 | 是 |
| 元件操作 / 启停设备（MachineOperate） | 是（中等级起；二次确认 + 审计） | 是 | 是 | 否 |
| 修改设备/工艺参数（MachineConfig） | 否 | 是（高等级；二次确认 + 审计） | 是 | 否 |
| 手动调试（MachineOperate；涉及参数需 MachineConfig） | 否 | 是 | 是 | 否 |
| 点表配置（MachineConfig） | 否 | 是（高等级） | 是 | 否 |
| 用户管理（UserManage） | 否 | 否 | 是（高等级；二次确认 + 审计） | 否 |
| 备份恢复 | 否 | 否 | 是 [权限点待定] | 否 |

> **权限按现状冻结**（2026-10-05 确认）：上表（含 `LogView` 对全部角色开放）即为需求基线。
> 后续任何调整（收紧或放宽 `AccessRules`）都属于需求变更，须走 §15.2 变更记录并由 [甲方/负责人] 批准。
>
> **UI 隐藏不等于权限控制**：所有业务方法入口必须做权限校验并记录审计（当前已按此实现）。
>
> ⚠️ **新框架的过渡实现与本表不一致（2026-10-31 记录）**：`AxisFramework.slnx` 已交付
> “本地账号 + 用户管理”的最小闭环 —— 5 角色（观察员/操作员/工艺工程师/设备工程师/管理员）、
> 无安全等级、口令可选（未设置即工位信任），登录与用户增删改均由本地用户目录承载，
> 见 [11-authorization.md](module-design/11-authorization.md)。它**不用于验收 AC-005**；
> 与本节冻结基线的统一（角色集合、安全等级、认证方式、锁定/改密策略）属于需求变更，

**运行时动态化（改配置不重启即生效）当前不具备**：`DevicesOptions` 为 `IOptions` 静态绑定，
且无配置重载的 UI 入口。已确认列为**后续独立变更**（前置条件：变更计划里程碑 B 的"注销时取消未决命令"路径）。

## 12. 安全与可靠性

- 断线重连（退避 + 抖动）、超时重试、心跳。
- 写后读回确认（未达期望判超时/失败）。
- 非法地址、越界值拦截（入队前校验，不发报文）。
- 权限不足拒绝写入并记录审计。
- 操作互锁（如伺服未使能拒绝运动命令；故障未复位拒绝使能）——**互锁只是操作合理性校验**。
- **急停、互锁、限位由 PLC/硬件完成**。
- 日志本地滚动，异常可追溯。
- 登录失败 5 次锁定 15 分钟；密码 PBKDF2-SHA256（迭代 600000，不低于 210000 强制下限）；
  会话空闲超时 30 分钟（滑动过期，可配置，0 表示不过期）。
- 数据库定期备份 [随 FR-014]。
